07 · API limitations
08 / 16

URL Inspection API Has a Fixed Daily Limit

The URL Inspection API is useful for URL-level verification, but it is not designed to inspect an entire 368K+ URL website one URL at a time.

2,000
URL inspections per day per Search Console property
600
URL inspections per minute per Search Console property
368.6K+
URLs known to Google on isbul.net
What I will not do

Inspect every URL blindly

The daily API limit makes a full URL-by-URL inspection inefficient and unnecessary. Randomly spending the quota would not produce a useful diagnosis.

What I will do

Inspect representative URL groups

I will use the API on carefully selected URLs from each major page type and each important GSC issue so the results reveal patterns.

Example sampling approach

08 · Data sources
09 / 16

No Single API Can Explain the Whole Problem

Each data source answers a different question. The value comes from combining them and comparing the results.

URL Inspection API

What does Google say about this URL?

Used for selected URL-level indexation checks, including Google's reported index status and canonical information.

Search Analytics API

Does this URL receive search visibility?

Used to analyze clicks, impressions, queries and pages that actually appear in Google Search performance data.

Sitemap Data

Which URLs are intentionally submitted?

Used to compare the site's intended indexable URL set with the URLs Google has discovered.

Server / CDN Logs

What is Googlebot actually crawling?

Used to measure crawl activity, request frequency, response codes and the sections receiving Google's attention.

URL Inventory + GSC APIs + Sitemaps + Server Logs = Indexation Diagnosis
Search Analytics API limitation Search Analytics is valuable for search-performance analysis, but it should not be treated as a complete index inventory. The full diagnosis therefore combines API data with the actual URL inventory, GSC indexation reports, sitemap data and Googlebot logs.
The goal is to connect discovery, crawling, indexing and search visibility into one picture.
Multiple data sources will be cross-checked isbul.net

11 / 16

The audit will trace real URLs, not just list issues

Example

Duplicate / canonical URL

Suppose GSC reports a URL such as:

The analysis will check:

1HTTP response: 200, 301, 302, 404, 5xx
2Canonical target
3Internal links pointing to it
4Sitemap inclusion
5Googlebot request frequency
6Redirect destination relevance
Decision

The URL then gets a clear treatment

Based on the evidence, the recommendation can be different for different URL groups.

Keep Canonicalize Redirect Noindex Block Remove
Why this matters A redirect, noindex or robots.txt rule is not automatically wrong. The right decision depends on the page's purpose and how Google is reaching it.

URL architecture

Duplicate paths, filters, parameters, legacy URLs and URL combinations.

Indexation signals

Canonical, noindex, robots.txt, sitemap and HTTP status alignment.

Internal links

Important pages, orphan pages and links leading to low-value URL variants.

10 · Full job scope
14 / 16

What the full engagement will actually cover

The job moves from broad GSC reporting to evidence-based diagnosis and a practical implementation plan.

Phase 1

Complete URL inventory

Build a categorized view of the site's URLs and page templates. Map each group to sitemap status, indexation status and technical signals.

Phase 2

Sitemap analysis

Compare sitemap URLs against the real URL inventory and find missing, duplicate, redirected or non-indexable entries.

Phase 3

GSC indexation analysis

Study the main exclusion classes and inspect representative URLs from every important page family.

Phase 4

Googlebot log analysis

Measure where Googlebot spends crawl activity, how often it reaches important sections and which low-value URLs consume requests.

Phase 5

Category-level comparison

Calculate crawl rate, index rate and exclusion patterns for job, company, position, department and filter URL types.

Phase 6

Technical diagnosis

Trace canonical, robots, noindex, redirects, 404, 5xx, internal links, duplication and page-quality patterns.

Phase 7

Competitor comparison

Compare the URL and page structures of major Turkish job platforms and identify useful differences.

Phase 8

Action plan

Turn findings into specific technical changes, examples, priorities and a clear sequence for implementation.
